# Контракт выбора модели для Plan mode

Этот документ задаёт постоянное поведение форка. Он не зависит от версии upstream, коммитов, имён внутренних событий или структуры кода.

Ребейс, рефакторинг и обновление upstream сохраняют этот контракт и текст документа. Если новая реализация нарушает контракт, исправляют реализацию. Изменять контракт можно только по явному запросу пользователя на изменение поведения.

## Назначение

Пользователь выбирает отдельную модель и reasoning effort для Plan mode. Эти настройки позволяют планировать одной моделью, а выполнять работу другой.

Выбор модели сам по себе не переключает режим. Plan mode остаётся активным до явного переключения режима пользователем.

## Настройки и эффективные значения

Есть 2 пары настроек:

- Глобальные `model` и `model_reasoning_effort` задают значения для Default mode.
- `plan_mode_model` и `plan_mode_reasoning_effort` задают переопределения для Plan mode.

В Plan mode сначала действует встроенный preset режима. Затем каждое заданное переопределение заменяет соответствующее значение preset. Если preset не задаёт значение, действует глобальное значение. Отсутствие одного переопределения не отменяет другое.

Сброс переопределения возвращает соответствующее значение встроенного preset. Конкретные значения preset могут меняться вместе с upstream.

Корневая конфигурация и профили поддерживают обе настройки Plan mode. Выбор сохраняется в конфигурации пользователя с учётом активного профиля.

Проверка конфигурации признаёт `plan_mode_model` и `plan_mode_reasoning_effort` на корневом уровне и в профилях. Эти поля не вызывают предупреждение о неизвестной настройке. Ошибки написания других полей по-прежнему вызывают предупреждение.

## Обычный выбор модели в Plan mode

После выбора обычной модели и reasoning effort интерфейс предлагает область применения:

| Выбор | Глобальные настройки | Настройки Plan mode | Активный режим |
| --- | --- | --- | --- |
| Только Plan mode | Сохраняются | Получают выбранную модель и effort | Plan mode |
| Все режимы | Получают выбранную модель и effort | Получают выбранную модель и effort | Plan mode |

Запрос области появляется и при смене только модели, и при смене только reasoning effort. Совпадение effort не позволяет пропустить запрос при выборе другой модели.

До выбора области интерфейс не меняет и не сохраняет глобальные настройки. Отмена запроса сохраняет прежние настройки и режим.

Запрос можно пропустить для полного отсутствия изменений: выбранная пара уже совпадает и с эффективной парой Plan mode, и с глобальной парой. Если пары различаются, запрос позволяет явно синхронизировать все режимы.

## Переключение режима и отправка сообщения

При входе в Plan mode применяются эффективные значения Plan mode. Следующее сообщение использует Plan mode и его модель с reasoning effort.

При выходе в Default mode восстанавливаются глобальные модель и reasoning effort. Повторный вход в Plan mode восстанавливает его переопределения.

Восстановление состояния потока и обновления состояния сервера сохраняют это разделение. Они не превращают выбор «Только Plan mode» в глобальную настройку.

## Сохранение и восстановление

Обе области выбора сохраняют модель и reasoning effort совместно. Новый запуск и возобновление потока читают сохранённые переопределения, включая настройки активного профиля.

Глобальные настройки остаются независимыми после выбора «Только Plan mode», перезапуска и возобновления потока.

## Исключение Luna Reserve

Luna Reserve сохраняет отдельное временное поведение. Этот выбор обходит обычный запрос области и не сохраняется как постоянная глобальная настройка или переопределение Plan mode.

## Проверка контракта

Проверка использует разные обычные модели с одинаковым effort. Она проходит через настоящий интерфейс выбора модели и проверяет обе области применения.

Проверка подтверждает активный Plan mode, пару следующего сообщения, переключение Default → Plan, перезапуск, возобновление и профили. Отдельно проверяется временное поведение Luna Reserve.

Тесты и снимки интерфейса подтверждают контракт. Успешная сборка и вывод версии не заменяют проверку поведения.

Текущая процедура проверки находится в [plan-mode-acceptance.md](skills/123-rebase-plan-mode/references/plan-mode-acceptance.md). Процедура может адаптироваться к новому коду; этот контракт сохраняется.

## Сохранение в истории форка

Документ и ссылки на него входят в первый downstream-коммит с навыками и инструкциями. Реализация Plan mode входит во второй downstream-коммит.

При каждом ребейсе, перегруппировке истории и выпуске документ переносится с форком без изменений. Старые коммиты и тесты не заменяют контракт.

Все проектные навыки учитывают этот контракт, если задача затрагивает Plan mode, конфигурацию модели, восстановление потока или перенос downstream-истории.
